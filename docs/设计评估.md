# MIDI Looper 设计评估

> 对象：Cardputer-Adv + M-VAVE FM-1（Sloop）USB MIDI 循环叠录固件  
> 评估日期：2026-11-09  
> 输入：设计简述 11 条（USB Host、叠录、分通道、1–32 小节、BPM、节拍器、首音起录、Enter 播放/停止、S 保存、文件管理器、两个标签页）  
> 参考基线：`Cardputer_MIDI` v0.8.2（USB Host + RECORDER 已跑通到可编译/离屏测试，真机仍是实验状态）

**一句话结论：可行，而且复用面很大；但这份简述里有 4 个决定成败的语义没定义——循环长度怎么定、叠录从哪个相位开始、BPM 跟谁走、节拍器从哪出声。这 4 个不定，做出来大概率是“能录、不能叠、循环不对拍”。**

以下按 **Cardputer-Adv** 评估（你写的 “VDA” 我按 Adv 处理；如果 VDA 是另一个型号，SRAM/Flash/USB 预算要重算）。

## 1. 需求转译：这 11 条在工程上到底要什么

| # | 设计条款 | 工程含义 | 现状判断 |
|---|---|---|---|
| 1 | USB Host 连 FM-1 Sloop | ESP32-S3 USB-OTG Host，同时开 MIDI IN + OUT，FM-1 自供电 | 已有实验代码，**最大不确定性** |
| 2 | 支持叠录 MIDI | 循环播放的同时继续采集，按循环相位合并 | 现有 RECORDER 只做单次录制，**语义要重写** |
| 3 | 区分 CH1/2/3/10 | 4 条 lane，事件保留通道；按 (ch,note) 配对 note-off | 现有录音器有通道掩码，可复用 |
| 4 | 循环 1–32 小节 | 循环长度 = 小节数 × 拍数 × PPQN，固定长度 | 必须由小节数决定，不能由“第二次按键”决定 |
| 5 | 用户选 BPM | 内部时基，决定小节时长；改 BPM 时循环整体变速 | 与 FM-1 F8 clock 的优先级**未定义** |
| 6 | 节拍器，录音时可开/关 | 本地 click，强拍重音；不能进 USB，否则被录进去 | 本地 I2S 路径可用，但被“连接即静音”挡住 |
| 7 | 首音起录，再按停止 | 第一次录音的 origin = 第一个音符 | 只适用于第一次；叠录不能这样 |

| 9 | S 保存为 `/MidiLoop/*.mid` | SMF Format 0/1，480 PPQN，循环长度写进 EOT | 现有 writer 可改 |
| 10 | 文件管理器删除/改名 | 扫描 `/MidiLoop`，只显示 `.mid`，D/N 操作 | 现有 library + 删除/改名逻辑可复用 |
| 11 | 两个标签页 LOOP / FILE | 240×135 sprite UI；设置项需要塞进 LOOP 页 | 可行，但布局要设计 |

## 3. 关键设计评估

### 3.1 循环长度与“第二次按键停止”——当前描述自相矛盾（最高优先级）

你的第 4 条说“循环 1–32 小节”，第 7 条说“再按一次停止录制”。这两条同时成立时，循环长度到底由谁决定？

- 如果由“第二次按键”决定：用户按在 3.7 小节，循环就是 3.7 小节，和“选了 4 小节”冲突；而且每次叠录的循环长度都可能不同。
- 如果由“小节数”决定：第二次按键只能算“提前收尾”，不能改变长度。

**建议的确定语义（写进设计案）：**

1. 循环长度 `loopLen = bars × beatsPerBar × 480` ticks（4/4、480 PPQN；32 小节 = 61,440 ticks）。
2. 第一次录音：按 `R` → `ARMED`；收到第一个所选通道音符 → 从 tick 0 开始录；录满 `loopLen` **自动停止并进入播放**。
3. 录满前再按 `R`：**提前收尾但保持 `bars` 不变**，尾部补静音；UI 显示 `LOOP 4 BAR`，不要偷偷改成 3 小节。
4. 已有循环时按 `R`：进入叠录（见 3.2），不是重新定义长度。
5. 想改长度：先停止，改 `bars`，再 `CLEAR` 重录；不要在播放中改长度。

这样“第二次按键”只承担“提前结束/放弃本次”的职责，循环长度始终可预测。

### 3.2 叠录的相位：不能再用“第一个 MIDI 起录”

第一次录音用“首音定 origin”是合理的：它把第一个音定义成第 1 小节第 1 拍。但叠录时循环已经在跑，origin 已经存在；此时再等“第一个 MIDI”没有任何意义，只会把整次叠录推迟。

**建议：**

- 已有循环且正在播放时按 `R`：**立即开始叠录**，事件 tick = 当前循环相位 + 距按键的偏移（对 `loopLen` 取模）。
- 已有循环但已停止时按 `R`：从 tick 0 开始播放并叠录。
- 叠录再按 `R`：结束本次叠录，已采集的事件保留；循环继续播放。
- 录满一圈自动结束本次叠录，循环无缝继续。

**实现上不要边播边改播放列表。** 建议：

- `loopBuf`（正在播放，已排序）与 `takeBuf`（本次叠录，按到达顺序）分开；
- 叠录结束时在**主任务**里把 `takeBuf` 排序、合并进 `loopBuf`，在循环边界原子切换（双缓冲或 `pending` 标志 + 边界合并）；
- 不要在音频任务里做 `memmove/qsort`——8192 条事件的合并会顶掉音频块。

**内存别翻倍**：双缓冲会把事件池 ×2。第一次录音时循环还没播放，可以直接写主池；**叠录一次只针对一条 lane**（用 `1/2/3/4` 选 lane），`takeBuf` 只留该 lane 的 2,000–4,000 条（16–32 KB），循环边界合并进主池。这样是“主池 64–96 KB + staging 16–32 KB”，而不是 2×96 KB；同时也符合“一次叠一个声部”的实际用法。若一定要 4 通道同时叠录，再评估 2×96 KB 的预算（见 3.5）。

### 3.3 时钟与 BPM：谁做主，必须先定

现有播放器的逻辑是“FM-1 发 F8，就按 FM-1 的 BPM 改播放速度”（`main.cpp:835-845`）。Looper 不能照搬：

- 你的第 5 条要求“用户可以选择 BPM”，这暗示 **Cardputer 自己是时基主人**。
- 现有 USB 输入只处理 `0x80–0xEF` 和 `F8`，**不解析 FA/FB/FC**（`usb_midi_host.cpp:82-86`）。也就是说，即使 Sloop 发 Start/Stop，现在也收不到；没有走带相位，无法和 FM-1 的 sequencer 锁第 1 小节。
- 因此：**默认内部 BPM 为主**；F8 只用来显示“FM1=120”或可选的“跟随”，不要自动覆盖用户 BPM。
- 如果用户同时开 FM-1 的 sequencer，两者只能靠“手动设成同一 BPM”保持不漂移，**没有小节相位锁定**；这一点必须写进限制，否则会被当成 bug。
- 真要做同步，下一阶段再加：解析 FA/FB/FC + 确认 Sloop 支持 USB 外部时钟（`SYNC=EXT`），这是另一个项目量级。

**时基建议**：循环位置用音频帧计数推进（64 帧 = 1.45 ms），不要用 `millis()` 或自由跑的 `esp_timer`。音频块是唯一和 click 同源的时钟，循环边界和节拍器天然对齐；`i2s_write` 阻塞时块数仍然守恒，不会漂。

**输入侧时间戳**：USB 输入回调跑在 `usb-midi` 任务里（`usb_midi_host.cpp:71-92`），事件时间要用“块计数 + 块内 µs”换算成 tick，而不是 `millis()`；1–2 ms 的 USB 投递抖动在 480 PPQN / 120 BPM 下约 1–2 tick，听感可接受。若要求更紧，让音频任务每块发布一个原子 `loopPosTick`，输入回调读它并加块内偏移。

**前提设置**：Sloop 侧 `GLO → MIDI` 的 CH1/2/3/10 映射、`OUT=KEYS/SEQ`、`CLOCK=OUT` 是运行前提（`firmware/README.md:67-73`），固件无法替代。若 FM-1 的 sequencer 正在跑，第一个音符可能来自 sequencer 而不是键盘，loop 的 origin 会被它定义；录键盘前先停 sequencer。

### 3.4 通道模型：4 条 lane，而不是“一个数组里混着 4 个通道”

第 3 条“区分 CH1/2/3/10，避免 MIDI 混乱”有两种实现：

- **A. 一条事件表 + 通道标签**：实现最简单，但 UI 只能整体显示，无法单独 mute/solo/清除某一路。
- **B. 4 条 lane，同一循环长度**：每条 lane 独立计数、独立 mute/solo、独立“LANE FULL”；保存时保留通道信息（MVP 单轨多通道，后续可 Format 1 分轨）。推荐 B。

无论 A/B，必须做到：

- note-off 按 `(channel, note)` 配对，不能只按 note（现有播放器已经这么做，见 `midi.cpp` 的注释与 `audio.cpp:111` 的 ch10 跳过逻辑）；
- 通道 10 鼓：本地合成器跳过，但事件保留并发给 FM-1（现有 `apply()` 已是这个行为，`audio.cpp:99-119`）；
- 录音过滤只收 1/2/3/10，其它通道丢弃并计数（可用 UI 小字提示 `IGNORED n`）。

### 3.5 事件容量：32 小节 × 4 lane 的真实上限

按 4/4、480 PPQN 算：

| 场景 | 每 lane 音符 | 每 lane 事件 | 4 lane 事件 | RAM（8 B/条） |
|---|---:|---:|---:|---:|
| 16 分音符单音 | 512 | 1,024 | 4,096 | 32 KB |
| 32 分音符单音 | 1,024 | 2,048 | 8,192 | 64 KB |
| 16 分音符 4 音和弦 | 2,048 | 4,096 | 16,384 | 128 KB |

现有录音器上限 **6000 条（48 KB）**（`midi_recorder.h:23`）。它够 16 分单音，但 **32 分单音就会截断，4 音和弦差 2.7 倍**。MIDI 播放器把上限设到 14,000 条 / 112 KB（`config.h:32`），说明 96 KB 在现有内存预算内，不算激进。

**建议：**

- 总上限 **12,000 条（96 KB）**，每 lane 上限 4,000 条；或总 8,192 条（64 KB）+ 明确“32 小节只保证 16 分单音”。
- 事件存 **tick（uint32）**，不存 µs；改 BPM 时循环自动整体变速，不用重算。
- 结构保持 8 B：`uint32 tick; uint8 type, note, vel, ch;`。
- 超限时停止该 lane 的录制、UI 显示 `LANE FULL`，不要静默丢事件。

**内存账**：主池 12,000 条 = 96 KB；如果叠录 staging 也做 12,000 条，就是 192 KB，加上 65 KB sprite 和 ~35 KB 静态约 292 KB——512 KB 能放下，但 heap 余量会明显小于现在能跑的播放器（约 212 KB）。按 3.2 的“单 lane 叠录”方案，staging 只需 16–32 KB，总占用回到 ~200 KB 以内。

### 3.6 节拍器：本地出声，但现在的“连接即静音”会把它一起掐掉

`usbConnectCallback()` 里 `audio.setMuted(connected)`（`main.cpp:372`），连接 FM-1 后本地音频被静音。好消息是 `_muted` 只把输出 buffer 清零，**I2S 任务继续跑**（`audio.cpp:200-214`），所以 click 可以在静音判断之后混进去，不需要重新初始化 codec。

**建议：**

- click 在音频任务里合成并混音，**放在 `_muted` 分支之后**，不受“本地钢琴静音”影响；
- 音色照 `metronome.cpp` 的配方：28 ms 正弦、重音 2 kHz、普通 1.35 kHz，强拍重音；
- 不要把 click 从 USB 发给 FM-1：它会被录进 loop（如果通道在过滤范围内），或者被 FM-1 当音符发声；
- 音量独立于主音量，NVS 保存；
- 录音时默认开 click，播放时可选择开/关；再加一个“1 小节 count-in”开关，用户体验会好很多。

### 3.7 保存与文件管理

- 目录 `/MidiLoop`；文件 `LOOP_0001.MID` 起步即可，想带信息可 `LOOP_120_4_0001.MID`（注意 UI 只显示 26 字符）。
- **MVP 用 Format 0、480 PPQN、单轨、多通道**；`EOT` 必须落在 `loopLen`，而不是最后一个事件，否则再导入时长度不对。
- 保存前先停录音；播放中可以保存，但要在主任务做，且保存期间禁止改循环；更稳妥是“停止播放 → 保存 → 恢复”。
- 写文件建议 `临时文件 → rename`，至少每 N 条 `yield()/delay(1)` 喂 watchdog；现有 writer 是逐条 `f.write`，8192 条要评估耗时。
- 文件管理器直接复用 `library.cpp`（只收 `.mid/.midi`，最多 64 项，`config.h:35`）+ `main.cpp` 的删除/改名；删除正在播放的循环前先停止。
- 没有 SD：循环留在 RAM，`S` 提示 `NO SD`，不要崩。

### 3.8 UI 与按键：两个标签页够，但设置项要有地方放

240×135，去掉 13 px 顶栏 + 11 px 底栏，剩 111 px。LOOP 页可以这样分：

```
┌──────────────────────────────┐
│ LOOP | FILE                  │ 13 px 标签栏
├──────────────────────────────┤
│ REC ●  BAR 2/4   BPM 120     │ 走带/位置
│ ████░░░░░░░░░░░░  (循环进度) │
│ CH1 LEAD  ▓▓▓▓░░  ON        │ 4 lane
│ CH2 PAD   ▓░░░░░  ON        │
│ CH3 BASS  ▓▓░░░░  ON        │
│ CH10 DRUM ▓▓▓▓▓▓  ON        │
├──────────────────────────────┤
│ R REC  ENT PLAY  S SAVE     │ 11 px 提示
└──────────────────────────────┘
```

BPM / 小节数 / 节拍器开关不要另开第三页，用 `Fn` 组合键 + 屏幕上的一条设置条/浮层即可；两个标签页是合理的。

**按键冲突要提前定：**

| 键 | LOOP 页 | FILE 页 |
|---|---|---|
| `R` / `Space` | 录音/停止录音 | — |
| `Enter` | 播放/停止 | 打开/确认（建议只做选择，不做播放） |
| `S` | 保存 | — |
| `Tab` | 切到 FILE | 切到 LOOP |
| `Fn` + `,` / `.` | BPM −/+ | — |
| `Fn` + `;` / `/` | 小节数 −/+ | — |
| `M` | 节拍器开/关 | — |
| `D` / `N` | — | 删除 / 改名 |
| `Bksp` | 停止并回 idle | 返回 |

注意：现有播放器里 `Space` 是播放/暂停；looper 里 `Space` 变录音，`Enter` 才是播放。这个改动要写在 README/速查表里，否则用户会按错。

### 3.9 监听与 Thru：先确认 FM-1 键盘是否本地发声

现有 Host build 的输入回调只做 `rec.add()`，**没有把输入回送到输出**（`main.cpp:749-751`）。这说明之前的假设是：FM-1 自己的键盘会本地发声，Cardputer 只负责录和回放。

Looper 必须确认这一点：

- 如果 FM-1 键盘本地发声：**不要加 thru**，否则同一音符在 FM-1 上响两次（或录两次）。
- 如果 FM-1 是纯控制器、本地不发声：必须加 thru，输入→输出延迟要控制在几 ms，并且要防止“自己的回放被再次录入”。
- 还要确认 Sloop 是否把 USB IN 回传到 USB OUT（soft thru）。如果会，循环回放的音符会被再次采集，形成反馈；这种情况下必须关掉 Sloop 的 thru，或在固件里过滤“刚发出的音符”。
- Sloop 的 ARP / quantize 如果作用在 USB IN 上，会把 loop 回放的音符改掉；确认 `ARP MODE=OFF`（`HOLD` 也要 OFF，见 3.10），否则“录进去的”和“放出来的”不一致。

这是**真机第一项要验证的行为**，不是代码能推出来的。

另外一个体感问题：loop 回放要经 USB 到 FM-1，比键盘本地发声多 2–5 ms 的链路延迟；叠录时以耳朵听到的 loop 为准，不要以屏幕位置为准。这个延迟不影响录制时间戳，但会影响“跟弹”的手感，UI 上不要把播放头做成唯一参考。

### 3.10 停止/边界/挂音

- 停止、循环边界、切页、拔线都要发显式 Note Off（按活动音符表），再补 CC64/CC121/CC123/CC120；现有 `usbMidi.panic()` 已实现（`usb_midi_host.cpp:334-358`）。
- Sloop 的 `ARP 2 → HOLD` 会锁住音符，Note Off 也放不掉（`firmware/README.md:84-89`）。这是 Sloop 侧设置问题，但 looper 的“停止后挂音”排查要先看它。
- 循环边界上跨界的音符（例如 2 小节的长音）：建议允许它延续到下一次循环的对应位置发 Note Off；不要在每个循环边界无脑 all-notes-off，否则 pad 会被切碎。
- 录音结束（自动或手动）时，对仍未收到 Note Off 的音符补一个 off（tick = 结束点或 `loopLen`），否则循环里会留一个永不停的长音。
- USB 输出队列 `QSIZE=1024`，`push()` 满时静默丢弃（`usb_midi_host.cpp:268-274`）。looper 要加溢出计数；一旦丢包，至少补一次 panic，避免 note-off 丢失造成挂音。

## 4. 风险清单（按优先级）

## 5. 必须在开工前补的规格决策

建议直接把下面这段作为设计案的“行为契约”：

1. **循环长度**：由 `bars` 决定；`loopLen = bars × 4 × 480` ticks（4/4）。
2. **第一次录音**：`R` → ARMED；首个所选通道音符 → tick 0 起录；录满自动停；再按 `R` = 提前收尾并补静音。
3. **叠录**：已有循环时 `R` 立即按当前相位叠录；再按 `R` 结束；录满一圈自动结束；循环不停。
4. **Enter**：播放/停止；停止时 panic。
5. **BPM**：内部为主；F8 仅显示/可选跟随；不自动覆盖用户 BPM。
6. **小节数**：1/2/4/8/16/32；改长度前必须停止并 CLEAR。
7. **节拍器**：本地 click，录音时默认开，可 `M` 切换；可选 1 小节 count-in；不进 USB。
8. **通道**：4 lane（1/2/3/10），同长度；每 lane 可 mute；其它通道忽略并计数。
9. **保存**：`/MidiLoop/LOOP_xxxx.MID`，Format 0、480 PPQN、EOT 在 loopLen；保存前停止录音。
10. **文件管理**：只显示 `.mid`；删除/改名复用现有逻辑；播放中禁止删除。
11. **Thru**：默认关闭；只有确认 FM-1 本地不发声才加。
12. **异常**：无 SD 可录不可存；USB 断开停止录音并 panic；循环保留在 RAM。

## 6. 建议的代码结构

```
src/
├── loop.h/.cpp        # 纯 C++ 循环引擎：tick 时基、状态机、采集/合并/调度
├── loop_store.h/.cpp  # SMF Format 0 writer/reader，/MidiLoop
├── metronome.h/.cpp   # click 合成 + 混音（音频任务调用）
├── usb_midi_host.*    # 复用；加输入时间戳钩子、溢出计数、可选 FA/FB/FC
├── library.*          # 复用；根目录改 /MidiLoop
├── ui.*               # 两个标签页 + 设置浮层
└── main.cpp           # 按键、NVS、SD、状态接线
```

**任务划分（沿用现有架构）：**

- 音频任务（core 1，prio 20）：推进 loop 时钟、按 tick 发 USB 事件、混 click、执行 panic；**不做 SD、不做排序**。
- USB 任务（core 0，prio 5）：IN/OUT 收发；输入回调只做“带时间戳入队”。
- 主任务（core 1）：UI、按键、SD 保存、叠录结束时的排序合并。

**循环状态机（建议 6 态，显式转换）：**

```
IDLE ──R──> ARMED_FIRST ──首音──> REC_FIRST ──录满/再按R──> PLAYING
  ↑                                     │
  └──────────────CLEAR/停止─────────────┘

PLAYING ──R──> OVERDUB ──再按R/录满──> PLAYING
PLAYING ──Enter──> IDLE（panic）
```

每个状态都要有“USB 断开 / SD 失败 / 超时”的退出路径；`ARMED_FIRST` 超过 10 s 没有音符就回到 IDLE 并提示（避免永远挂着）。

**事件结构：**

```cpp
struct LoopEvent {
    uint32_t tick;   // 0..loopLen-1, 480 PPQN
    uint8_t  type;   // ON/OFF/CC64/CC1/PB
    uint8_t  note;   // 或 CC 号 / PB LSB
    uint8_t  vel;    // 或 CC 值 / PB MSB
    uint8_t  ch;     // 0..15
};                   // 8 B
```

如果想把 lead 做得像样，建议把 **Pitch Bend（0xE0）和 CC1（调制轮）** 也纳入事件类型；现有 RECORDER 只录 Note/CC64，loop 里的 lead 会显得很“死”。这是低成本高收益的补充。

## 9. 最终建议

1. **先把 3.1 的“小节数定长度、第二次按键只提前收尾”写死**；否则叠录功能一定返工。
2. **叠录不要等首音，也不要等循环边界**：按当前相位立即录，loop 边界合并；这是 looper 和 recorder 的本质区别。
3. **BPM 以 Cardputer 为主，F8 只做显示/可选跟随**；不要假装能和 FM-1 sequencer 锁小节，除非后续补 FA/FB/FC 和 Sloop 外部时钟。
4. **节拍器走本地 I2S，放在 `_muted` 之后混音**；不要走 USB。
5. **M0 先验 USB 全双工和 Sloop thru/HOLD**，再写 UI；这是唯一可能推翻整个方案的风险点。
6. 容量按 **12,000 条 / 96 KB** 设计，不要沿用 6,000；32 小节在 32 分音符或和弦下会超。
